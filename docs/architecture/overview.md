# 系统架构概览

**版本**: v0.1
**最后更新**: 2026-08-02

## 1. 高层架构

系统分为三大层：

### 客户端（Godot 2D）
- 地图视图：渲染 2D 小镇地图
- Agent 查看器：点击 Agent 查看其状态、记忆和知识
- 对话面板：查看 Agent 之间或与玩家的对话
- 回放查看器：按 tick 回顾小镇历史
- 玩家控制：移动、互动、引入声明

### 服务器（Go）
- Tick 循环引擎：推进游戏时间
- 事件总线：世界事件的发布/订阅
- Agent 运行时：规则决策 + LLM 调用
- 知识引擎：KnowledgeClaim CRUD、传播、质疑
- API 层：WebSocket 实时同步 + HTTP 玩家动作
- 日志系统：事件/决策/知识日志

### 数据层
- PostgreSQL：持久化状态
- Redis：缓存/队列
- 向量数据库：语义记忆检索

## 2. 通信模式

| 从 | 到 | 协议 | 内容 |
|----|-----|------|------|
| Go 服务器 | Godot 客户端 | WebSocket | 状态增量、事件通知 |
| Godot 客户端 | Go 服务器 | WebSocket/HTTP | 玩家动作、视图请求 |
| Agent 运行时 | 知识引擎 | 进程内 | 创建声明、查询 |
| Tick 循环 | Agent 运行时 | 进程内 | Tick 信号、世界状态 |

## 3. Tick 流程

每个游戏 Tick 发生以下步骤：

1. Tick 循环触发
2. 世界状态推进（时间、天气、资源再生）
3. 调度事件分发到事件总线
4. 每个 Agent：
   a. 接收其地点的事件
   b. 更新记忆和知识
   c. 评估目标（效用评分）
   d. 执行行动（基于规则或 LLM）
   e. 记录决策
5. 状态增量广播给连接的客户端
6. 日志持久化

## 4. 扩展策略

### v0.1（10 Agent）
- 所有 Agent 在 Go 服务器进程内运行
- 无需数据库持久化（内存+可选存档）
- 简单 WebSocket 广播

### v1.0（100 Agent）
- 冷/温/热分层
- Redis 进程间通信
- PostgreSQL 持久化

### v2.0（1000+ Agent）
- Agent 分片跨多个 Go 进程
- 事件总线通过 Redis Streams
- 向量数据库语义记忆检索
