# K-town v0.3 分阶段实施计划

> **制定日期**: 2026-08-04  
> **版本目标**: v0.3 — "让小镇活起来"  
> **开发周期**: 2周（10个工作日）  
> **核心原则**: 深度优先于广度，玩法优先于技术，验证优先于完美

---

## 总览

```
Phase 1 (Day 1-3): Agent行为深度 —— 让Agent不再像机器人
Phase 2 (Day 4-6): 经济循环 —— 让金币有进有出，世界有供需
Phase 3 (Day 7-8): 玩家体验 —— 让玩家的每个选择都有意义
Phase 4 (Day 9-10): 整合验证 —— 确保一切协同工作
```

---

## Phase 1: Agent行为深度（Day 1-3）

### 1.1 目标
让每个Agent产生**不可预测但合理**的行为，玩家能观察到"这个Agent今天不太一样"。

### 1.2 任务分解

#### Task 1.2.1 — Agent个性系统 [Day 1, 上午, 4h]

**做什么**：
- 为每个Agent添加`personality`字段（5维人格模型：外向性/尽责性/开放性/宜人性/情绪稳定性）
- 根据人格维度影响决策权重：
  - 外向性高 → 社交概率+30%
  - 尽责性高 → 工作时间+20%
  - 开放性高 → 探索概率+25%
  - 宜人性高 → 帮助他人概率+20%
  - 情绪稳定性低 → 心情波动更大

**怎么做**：
```
agent.py:
- 在AgentIdentity中添加personality: Dict[str, float]
- 在populate_agents()中为每个Agent赋予独特人格
- 在decide()中引入人格权重调整
- 同职业Agent因人格不同产生行为差异
```

**验收标准**：
- [ ] 两个铁匠（一个勤劳一个懒散）在相同条件下做出不同选择
- [ ] 高外向Agent比低外向Agent社交频率明显更高
- [ ] 行为差异可以被玩家观察到

**风险**：人格参数调不好导致所有Agent行为趋同
**缓解**：先设置极端值测试，再调整到合理范围

---

#### Task 1.2.2 — 关系驱动行为 [Day 1, 下午, 4h]

**做什么**：
- 好感度影响Agent决策：
  - 好感>30 → 优先寻找对方、帮助对方
  - 好感<-10 → 回避对方、可能产生冲突
  - 好感>50 → 主动分享知识、赠送物品
- 关系变化有记忆：连续3天互动→关系升级

**怎么做**：
```
agent.py:
- decide()中检查在场Agent的好感度
- 高好感→优先选择talk/work nearby
- 低好感→选择move away或ignore
- 新增_check_social_preference()方法
```

**验收标准**：
- [ ] 好朋友们会主动聚集在一起
- [ ] 互相讨厌的Agent会避开对方
- [ ] 关系变化会影响每日摘要的叙事

**风险**：关系系统可能导致Agent扎堆或分散不均
**缓解**：设置关系影响的上限，不完全覆盖工作需求

---

#### Task 1.2.3 — 知识→决策影响 [Day 2, 上午, 4h]

**做什么**：
- Agent持有的知识影响其行为选择：
  - 持有"森林有狼"→减少去荒野
  - 持有"矿洞坍塌风险"→去矿洞时体力消耗+5
  - 持有"新草药配方"→医生治疗效果提升
  - 持有"商人缺货"→采集者更愿意卖货

**怎么做**：
```
agent.py:
- decide()中查询Agent持有的知识
- 根据知识内容调整行为权重
- 创建KnowledgeEvaluator类评估知识对当前决策的影响
```

**验收标准**：
- [ ] Agent因为持有特定知识而改变行为
- [ ] 知识改变行为的事件被记录到日志
- [ ] 玩家可以看到"Agent因为知道X所以做了Y"

**风险**：知识数量多时决策变慢
**缓解**：只考虑最近5条知识，按置信度排序

---

#### Task 1.2.4 — 情绪传染与事件响应 [Day 2, 下午, 4h]

**做什么**：
- Agent心情互相影响：
  - 周围有悲伤的Agent→自己心情也变差
  - 周围都是开心的Agent→心情变好
- Agent对事件有更丰富的反应：
  - 灾害事件→恐惧→寻找安全地点
  - 节日事件→开心→去广场庆祝
  - 知识冲突→困惑→寻找讨论对象

**怎么做**：
```
agent.py:
- think()中加入情绪传染逻辑
- _process_event()中增加心情变化幅度
- 新增_react_to_world_state()方法
```

**验收标准**：
- [ ] 一个Agent的心情会影响周围Agent
- [ ] 大事件后Agent行为有明显变化
- [ ] 情绪传染链可以被追踪

---

#### Task 1.2.5 — 轻量LLM辅助决策 [Day 3, 全天, 8h]

**做什么**：
- 在3种关键场景调用LLM：
  1. 情绪危机时（心情<20）："你很累且很低落，你会做什么？"
  2. 知识冲突时："你听到了两个矛盾的说法，你信哪个？"
  3. 社交困境时："你朋友需要帮忙但你很累，你怎么办？"
- 日常行为仍用规则引擎（省钱+快速）

**怎么做**：
```
llm.py:
- 新增crisis_decision()方法
- 新增resolve_conflict()方法  
- 新增social_dilemma()方法

agent.py:
- decide()中检测是否需要LLM介入
- 是→调用LLM→解析结果→执行
- 否→使用规则引擎
```

**验收标准**：
- [ ] LLM生成的决策合理且符合Agent性格
- [ ] 响应时间<3秒
- [ ] 每天LLM调用不超过10次（控制成本）

**风险**：LLM返回格式不稳定
**缓解**：使用JSON格式约束，失败时fallback到规则引擎

## Phase 2: 经济循环（Day 4-6）

### 2.1 目标
建立"资源→生产→交易→消费→再投资"的闭环，让金币有实际意义。

### 2.2 任务分解

#### Task 2.2.1 — 资源消耗系统 [Day 4, 上午, 4h]

**做什么**：
- 每个Agent每天消耗食物（1-3单位）
- 食物不足→体力下降加速→心情变差
- 工具/装备有耐久度，用完需要修理/购买

**怎么做**：
```
world.py:
- 资源每天自然恢复（食物+5/天在荒野）
- Agent每天消耗食物
- 体力消耗公式加入食物因素

agent.py:
- think()中加入食物消耗逻辑
- 食物不足时心情和体力额外下降
```

**验收标准**：
- [ ] Agent每天自动消耗食物
- [ ] 食物不足时Agent状态明显下降
- [ ] 资源随时间自然恢复

---

#### Task 2.2.2 — 供需价格系统 [Day 4, 下午, 4h]

**做什么**：
- 每种资源有基础价格和浮动价格
- 供>需→价格下降；供<需→价格上升
- 价格影响Agent行为：
  - 食物贵→农民更愿意种地
  - 工具便宜→更多人买工具

**怎么做**：
```
world.py:
- 新增price_system模块
- 每个地点有当前价格表
- 每天根据供需调整价格

agent.py:
- decide()中考虑价格因素
- 高价商品对应职业更愿意工作
```

**验收标准**：
- [ ] 价格每天波动
- [ ] 价格影响Agent行为选择
- [ ] 玩家可以查看价格趋势

---

#### Task 2.2.3 — 交易与产业链 [Day 5, 全天, 8h]

**做什么**：
- Agent之间自动交易：
  - 商人从铁匠买工具→卖给其他Agent
  - 农民产食物→卖给商人/直接卖给需要的人
  - 医生需要草药→从采集者购买
- 玩家可参与交易：
  - 买卖物品
  - 设定买卖价格
- 交易记录影响关系（公平交易+好感，欺诈-好感）

**怎么做**：
```
agent.py:
- 新增trade_evaluation()方法
- 商人Agent自动寻找低价买入高价卖出
- 其他Agent根据需求寻找卖家

api.py:
- 新增/api/trade端点
- 玩家可以挂单买卖
```

**验收标准**：
- [ ] Agent之间自动产生交易
- [ ] 交易记录在日志中可见
- [ ] 玩家可以参与买卖
- [ ] 产业链形成（农民→商人→消费者）

---

#### Task 2.2.4 — 玩家经济参与 [Day 6, 上午, 4h]

**做什么**：
- 玩家有真正的背包和金币
- 玩家可以：
  - 在广场摆摊卖东西
  - 投资Agent（给铁匠50金→铁匠效率+20%）
  - 购买服务（请医生治疗、让侦察兵探索）
- 玩家每天需要买食物（否则降体力）

**怎么做**：
```
agent.py:
- 玩家Agent继承所有经济功能
- 新增invest()和buy_service()方法

api.py:
- 玩家操作端点支持经济行为
- 新增/api/market查看市场信息
```

**验收标准**：
- [ ] 玩家需要每天买食物生存
- [ ] 投资Agent有回报
- [ ] 玩家行为影响市场价格

---

#### Task 2.2.5 — 经济平衡与通胀控制 [Day 6, 下午, 4h]

**做什么**：
- 金币回收机制：
  - 每天住宿费/食物费
  - 装备修理费
  - 技能学习费
- 经济指标监控：
  - 总金币/人均金币/基尼系数
  - 价格波动率

**怎么做**：
```
world.py:
- 新增economy_monitor模块
- 每天计算经济指标
- 根据指标调节资源刷新率
```

**验收标准**：
- [ ] 金币总量趋于稳定（非无限增长）
- [ ] 贫富差距可观察但不过度
- [ ] 经济指标每日摘要可见

## Phase 3: 玩家体验（Day 7-8）

### 3.1 目标
让玩家每天都有明确目标，每个选择都有后果，值得玩第二天。

### 3.2 任务分解

#### Task 3.2.1 — 行动点系统(AP) [Day 7, 上午, 4h]

**做什么**：
- 玩家每天12AP（每时段3AP）
- 不同行动消耗不同AP：
  - 移动：1AP
  - 工作：1AP
  - 社交：1AP
  - 探索：2AP
  - 交易：1AP
  - 休息：1AP（恢复体力）

**怎么做**：
```
agent.py:
- 玩家Agent添加ap字段
- 每个行动检查AP是否足够
- 每日0点重置AP

api.py:
- 玩家操作消耗AP
- 返回剩余AP
```

**验收标准**：
- [ ] 玩家每天必须做选择（不能什么都做）
- [ ] AP不足时行动被拒绝
- [ ] AP显示在UI上

---

#### Task 3.2.2 — 深度对话系统 [Day 7, 下午, 4h]

**做什么**：
- 与Agent对话有3轮选择
- 对话选项受好感度影响：
  - 好感<5：只有"打招呼"
  - 好感>15：解锁"聊天/赞美/请教"
  - 好感>30：解锁"帮忙/送礼/分享秘密"
- 对话结果影响关系和知识

**怎么做**：
```
agent.py:
- 新增dialogue()方法
- 根据好感度和性格生成对话选项
- 对话结果影响好感度和知识

api.py:
- 新增/api/dialogue端点
- 返回对话选项和结果
```

**验收标准**：
- [ ] 对话有多轮选择
- [ ] 选项受好感度影响
- [ ] 对话结果影响游戏状态

---

#### Task 3.2.3 — 事件链系统 [Day 8, 上午, 4h]

**做什么**：
- 事件之间有关联：
  - 传闻→调查→发现真相→小镇震惊→政策改变
  - 资源短缺→价格上涨→Agent转行→新平衡
  - 两个Agent吵架→关系恶化→派系形成→冲突事件
- 事件链有可视化时间线

**怎么做**：
```
events.py:
- 新增EventChain类
- 事件可以触发后续事件
- 记录事件因果关系

api.py:
- 新增/api/timeline端点
- 返回事件链数据
```

**验收标准**：
- [ ] 事件之间有因果关系
- [ ] 事件链可以被追踪
- [ ] 玩家可以看到"因为A所以B"

---

#### Task 3.2.4 — 每日目标与刷新 [Day 8, 下午, 4h]

**做什么**：
- 每天给玩家3个随机目标（从池中抽取）
- 目标示例：
  - "今天赚20金币"
  - "与3个不同Agent对话"
  - "在荒野探索2次"
  - "帮助一个Agent完成工作"
- 完成目标获得奖励

**怎么做**：
```
quests.py:
- 每日目标从随机池生成
- 进度实时跟踪
- 完成后发放奖励
```

**验收标准**：
- [ ] 玩家每天有明确目标
- [ ] 目标有进度显示
- [ ] 完成有奖励

## 风险登记

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| LLM调用成本过高 | 中 | 高 | 限制调用次数，缓存结果 |
| 经济系统失衡 | 高 | 中 | 设置参数上下限，监控指标 |
| 玩家学习曲线过陡 | 中 | 中 | 渐进式引导，默认推荐 |
| 性能瓶颈（>20 Agent） | 低 | 中 | Agent分批处理 |
| 行为多样性不足 | 中 | 高 | 人格系统+LLM补充 |
