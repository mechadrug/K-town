# v0.1 原型实施计划

**日期**: 2026-08-02
**目标**: 可游玩的 2D 小镇，10 个 Agent，3 个地点，5 种事件类型。

## 1. 范围

### 包含
- Go 服务器：tick 循环、事件总线、Agent 状态机
- Godot 2D 客户端：渲染地图、Agent 和基本 UI
- 10 个 Agent，带日常日程和规则决策
- Agent 通过观察创建 KnowledgeClaim
- Agent 间通过对话传播知识
- 玩家可以进入、移动并影响一个事件
- 事件日志和基本回放查看器

### 不包含（v0.1）
- LLM 集成（模拟/功能标志后）
- 数据库持久化（仅内存）
- Redis 或外部队列
- 向量数据库语义搜索
- 复杂社会组织（派系、团体）
- 战斗或死亡机制
- 自定义美术素材

## 2. 任务分解

### 阶段 1：Go 服务器基础
1. 项目骨架、配置加载
2. Tick 循环引擎
3. 世界状态 + 地点
4. 事件总线

### 阶段 2：Agent 系统
1. Agent 身份 + 状态结构体
2. Agent 记忆（短期 + 长期）
3. Agent 日程 + 目标评估
4. 规则决策引擎
5. Agent 生命周期（感知-思考-行动）

### 阶段 3：知识系统
1. KnowledgeClaim 结构体 + 存储
2. 声明传播逻辑
3. 质疑和固化

### 阶段 4：API + 网络
1. WebSocket 处理器
2. HTTP 端点（状态/日志）
3. 状态增量广播

### 阶段 5：Godot 客户端
1. 项目设置 + 主场景
2. 2D 地图渲染
3. Agent 精灵 + 移动
4. WebSocket 客户端
5. UI 面板（查看器、事件日志）
6. 玩家控制
7. 回放查看器

### 阶段 6：集成 + 打磨
1. 配置所有 10 个 Agent 原型
2. 实现 5 种事件类型
3. 日志管道
4. 端到端冒烟测试
5. 更新 handoff.md

## 3. 依赖关系

阶段 1（基础）-> 阶段 2（Agent）-> 阶段 3（知识）
                                  \-> 阶段 4（API）
阶段 4（API）-> 阶段 5（客户端）-> 阶段 6（集成）

阶段 2 和阶段 3 可并行运行（不同模块）。
阶段 5 在阶段 4 WebSocket 就绪后即可开始。

## 4. 验收标准

- go run cmd/server 启动服务器，tick 循环以 1Hz 运行
- 打开 Godot 项目显示带 10 个移动 Agent 的 2D 地图
- Agent 遵循日常日程（工作、社交、睡眠）
- Agent 观察事件时生成 KnowledgeClaim
- 同一地点的两个 Agent 交换知识
- 玩家可以移动并触发一个事件
- 回放查看器可以回顾一天的历史
- 所有事件出现在事件日志中

## 5. 风险与缓解

| 风险 | 缓解 |
|------|------|
| Godot WebSocket 版本兼容性 | 阶段 5.4 尽早测试连接 |
| Agent 行为过于随机/无聊 | 调整规则权重；增加更具体的规则 |
| 状态同步延迟或不一致 | 保持增量小；重连时发送完整状态 |
| 范围蔓延 | 严格 v0.1 边界；最多 10 Agent，v0.1 无 LLM |
