> **状态（2026-08-23）**：历史玩法设计；当前权威玩法为 `gameplay-design-v5.md`。
> **日期**：2026-08-04

> **配套**：历史功能安排见 `docs/plans/2026-08-04-gameplay-plan.md`；当前实施计划见 `docs/plans/2026-08-23-rebuild-plan.md`。

## 0. 一句话与三根支柱

**K-town 是一座有自己生活的边境小镇。你走进来，看它活着，然后成为一个居民。**

| 支柱 | 含义 | 反例（砍掉） |
|---|---|---|
| **见证** | 小镇的每一天是读不完的故事：谁和谁和好了、谁信了一条新传闻、谁今天很沮丧 | 用数值追赶压过观察 |
| **归属** | 你是一位居民，不是英雄；回报是"成为熟人"而非"征服小镇" | 声望传奇、以玩家命名建筑 |
| **惊奇** | 涌现不可预料：你的一个小行为引发连锁反应 | 固定任务树、脚本化剧情 |

## 1. 核心循环

### 1.1 世界的循环（始终在运行，游戏的心脏）

```
时间推进 → 事件发生 → Agent感知 → 思考 → 决策 → 执行动作 → 世界变化
   ↑                                                           ↓
   └──────────── 知识/关系/情绪/经济 演化 ← 行动后果 ←────────┘
```

关键：**决策必须执行**（Phase 0 已修复），否则世界是静止的。本设计所有系统都挂在这个循环上。

### 1.2 玩家的循环（每日）

```
醒来 → 读小镇脉搏（谁在哪/谁不开心/在传什么/今天什么天气）
     → 用 12 AP 行动（移动/工作/交谈/调查/休息/添知识）
     → 傍晚广场汇集 → 夜晚入睡
     → 读日报：今天小镇发生了什么、为什么
```

玩家的行动通过**与 NPC 完全相同的管线**（`tick._handle_action`）影响世界 —— 玩家不是 GM，是平等的一员，世界对玩家行为产生涟漪而非服从。

## 2. 五大系统（相互咬合的齿轮）

> 原则：五个系统**共享同一个反馈环**。一个系统的事件经由"感知→决策→行动"影响其它系统，而不是各跑各的状态机。

### 2.1 时间与节律 —— "活着"的骨架

- **一天 = 20 小时**（世界观：几十万年后地球转速变慢）。清醒 12 小时 + 睡眠 8 小时，清晨 5 点醒来。
  时段：清晨(5-9)/白天(9-14)/傍晚(14-17)/深夜(17-5)。
- **回合制**：玩家 1 AP = 度过 1 小时，行动驱动世界推进；点「休息」= 睡觉结束今天，跳到次日清晨、AP 重置为 12。夜晚拦截行动与对话。
- **居民生活节律**：清晨起床→工作(6-14)→傍晚收工广场聚集/社交(14-17)→深夜休息。
- **节奏变化**：天气日、集市日（每周）、节日（不定期）、灾害；小镇随居民攒钱逐级修缮重建（末世重建的可见弧线）。
- **验收**：玩家不看 UI，仅看地图就能读出"现在几点、什么天气、人们该在哪"。

### 2.2 关系 —— "社会"的纤维

- **双向好感 `social_ties`**：互动增长，疏于维护按日衰减（保持"关系需要维护"的压力）。
- **关系等级门控可见行为与对话**：
  | 等级 | 好感 | 行为 |
  |---|---|---|
  | 敌对 | < -10 | 回避、可能冲突 |
  | 陌生人 | -10 ~ 5 | 客气寒暄 |
  | 认识 | 5 ~ 15 | 可交易、聊近况 |
  | 熟悉 | 15 ~ 30 | 请教技能、帮忙干活 |
  | 朋友 | 30 ~ 50 | 主动分享知识/秘密 |
  | 挚友/知己 | > 50 | 影响其决策、改变其目标 |
- **关系产生可见行为**：好友并肩而坐、互相分享；宿敌互相回避；关系网自然涌现小圈子（派系 = 聚类结果，不是硬编码）。
- **玩家关系 = 进入小镇的桥梁**：好感决定居民对你的态度与开放度。

### 2.3 知识 —— "文化"的血液（K-town 招牌）

- **KnowledgeClaim 结构化知识**：观察/对话/传闻产生；传播时置信度衰减；冲突互相质疑；固化成为小镇"共识"。
- **知识驱动行为**（已接进 `decide()` 第 2 层）：
  - 听说"森林有狼" → 回避荒野；
  - 听说"矿价大涨" → 去采矿；
  - 信任某人 → 主动社交。
- **知识产生故事**：传闻 → 有人去调查 → 可能发现 → 小镇改变看法（事件链）。
- **玩家可以注入知识**：说一句话可能被传开，观察它如何改变小镇 —— 这是玩家最独特的"轻触"。
- **验收**：玩家能看到"因为 X 信了 Y，所以做了 Z"（日报/知识视图呈现因果）。

### 2.4 经济 —— "生存"的体温

- **生产 → 消费 → 交易 → 再投资**：工作产出资源 → 每日食物消耗 → 广场供需定价交易 → 金币回收防通胀。
- **价格随供需波动，波动驱动行为**：食物贵 → 农民多种、采集者多采 → 供给回升 → 价格回落。
- **玩家参与**：采集/制作/买卖/吃饭；背包与金币真实。
- **一条闭环示范（Phase 2 验收）**：`食物稀缺 → 涨价 → 更多人采集 → 价格回落 → 新的平衡`。
- 金币必须有**流出**（食物/维修/学习），否则通胀（已有 `_apply_gold_sinks`）。

### 2.5 情绪 —— "天气"的可见化

- **心情随时间/事件/关系/知识波动**，在人群间传染（稳定性高者抗传染）。
- **心情是地图上"一眼可读"的信号**：情绪光环颜色（绿=开心/蓝=平静/红=愤怒…）。
- **事件响应人格化**：灾害 → 恐惧 → 避难；节日 → 喜悦 → 广场；冲突 → 困惑 → 找人倾诉。

## 3. 事件系统 —— 涌现的引擎

- **每日日程事件**：天气/资源发现/社交相遇/物品制作/价格变化/传闻/节日/灾害（`events.py` 已实现）。
- **事件链**：传闻→调查→真相→政策变化；资源短缺→涨价→转行→新平衡（`_check_event_chains` 已实现，待完整）。
- **事件的归宿是决策**：事件经感知进入 Agent 决策，再经行动反馈世界 —— 事件不是孤立弹窗。

## 4. 玩家体验与信息架构（修复当前四类问题）

### 4.1 统一交互模型（修复"点击头像也能对话"的入口混乱）

```
点地图上的居民 ──→ 档案面板（看）：性格/心情/当前目标/最近日记/关系网/今天的活动
档案面板内 [交谈] 按钮 ──→ 进入对话（唯一入口）
行动栏 [聊天] 按钮 ──→ 与当前地点在场的一位居民开始对话（快捷方式，同一套对话系统）
```

**原则**：*点人 = 看人；交谈 = 一个明确的动作。* 删除重叠入口，交互只有一条清晰路径。

### 4.2 对话系统重设计（修复"聊天意义不明"）

对话必须**有语境、有后果、有门控**：

| 维度 | 设计 |
|---|---|
| **语境** | 话题由「Agent 性格 × 当前心情 × 关系等级 × 正在做的事/今天的事件」生成。同一个"闲聊"，对忧郁的铁匠和开朗的说书人是两段不同的对话 |
| **门控** | 选项随关系解锁：陌生人只能寒暄；认识可聊近况/问工作；熟悉可请教技能/帮忙；朋友可分享知识/秘密 |
| **后果** | 每次对话都改变可见状态：好感变化（有失败率）、知识交换（闲聊会传出自己的一条知识给在场者）、心情微调、可能触发事件（邀约、委托） |
| **记忆** | 重要对话写入对方日记/关系，成为之后话题的上下文（Phase 2） |

**验收**：和不同 Agent 对话内容不同；对话后能观察到好感/知识/心情的真实变化；日报提及"你今天和谁聊了什么"。

### 4.3 信息架构（修复"知识和任务不显示"+"第一屏"）

- **根因修复**：Tab 切换改为 JS 显式驱动 `style.display`（当前内联 `display:none` 覆盖 `.active` class，导致知识/任务 Tab 永远不显示）。
- **第一屏 = 小镇脉搏**，玩家数值只是角落：
  ```
  ┌─────────────────────┬────────────────────────┐
  │  地图（主舞台）       │  小镇脉搏（第一块）：    │
  │  ・居民按节律移动      │   现在几点/什么天气      │
  │  ・情绪光环颜色        │   谁在哪、谁不开心       │
  │  ・点人看档案          │   正在传的知识/传闻      │
  │  ・点地点看在场的居民   │   最新事件流            │
  │                     ├────────────────────────┤
  │                     │  任务（每日目标，3个）     │
  │                     ├────────────────────────┤
  │  行动栏：移动5地       │  知识（流动视图，招牌）   │
  │  /工作/交谈/调查/     │  ・谁信了什么→传给谁      │
  │  休息/添知识/重置      │  ・置信度涨跌/冲突/固化   │
  └─────────────────────┴────────────────────────┘
  ```

### 4.4 图标系统（修复"前端一堆 ?"）

- **根因**：`index-v2.html` 中图标为 emoji，GBK→UTF-8 转换中部分丢失；`app-v2.js` 有字面量 `??` 占位符。
- **设计**：建立单一图标来源 `icons.js`（emoji 映射表），全站统一引用；**全界面不允许出现字面量 `?` 占位符**；所有动态文本用 `textContent`，杜绝 innerHTML 注入乱码。
- **验收**：全界面无 `?`、无乱码、无重复图标定义。

## 5. 任务与目标 —— 薄层，不喧宾夺主

- **每日目标（3 个）**：从"真实可执行动作"池生成（采集 2 次 / 与 2 位居民交谈 / 赚 20 金 / 调查 1 次 / 传播 1 条知识），进度挂在动作执行上实时追踪，完成有奖励。
- **居民个人请求（薄层）**：居民基于自己的目标/处境偶尔提出具体请求（"帮我带 3 份食物""一起调查矿洞"），完成则关系大涨。这是**关系与处境的产物**，不是硬编码任务树。
- **明确取消**：5×5 技能树、声望等级、命名建筑、周排行榜 —— 玩家英雄泄漏，冻结不实现。

## 6. 数值与平衡（收敛到可调）

| 项 | 值 | 说明 |
|---|---|---|
| 玩家 AP | 12/天 | 移动1、工作1、交谈1、调查2、休息1、添知识1 |
| 体力 | 100 | 动作消耗、休息恢复、深夜睡眠恢复 |
| 食物 | 每日 1-3 消耗 | 不足则饥饿降体力/心情 |
| 金币 | 工作/交易流入，食物/维修/学习流出 | 回收机制防通胀 |
| 关系衰减 | 每日向 0 回缩 ~5% | 维持关系需要互动 |
| 知识置信度 | 传播 ×tie_strength 衰减，冲突互降 | 固化阈值 0.85 |

> 全部数值收敛到 `config.py`/参数常量，允许调参；**每个数值必须有可见原因**（日报/档案解释"为什么变了"）。

---

## 7. 明确不做什么（Non-goals）

- 不做玩家英雄成长线（技能树/声望/排行榜）。
- 不做脚本化剧情（叙事 = 涌现 + 事后总结，不是预设故事）。
- 不做多玩家/大规模（>20 Agent）——那是规模问题，不是原型阶段问题。
- 不做复杂生产链（星露谷式）——先做"一条食物闭环"示范。

---

## 8. 设计原则（评审时对照检查）

1. **一条闭环，做到可见** —— 任何新系统必须挂到"感知→决策→行动→世界变化"上。
2. **每个数字有可见原因** —— 世界不沉默，日报/档案/事件流解释为什么。
3. **深度优先于广度** —— 3 个接线良好的系统 > 10 个冻结的。
4. **玩家读小镇，不读 HUD** —— 信息架构是核心系统。
5. **玩家是居民，不是 GM** —— 玩家与 NPC 走同一条动作管线。
6. **先观察，后加入** —— 新手引导的第一个动作是"点一个居民，看他是谁"。
