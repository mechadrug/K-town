# K-town 世界自生成系统设计（Agent-Authored Content）

> **状态**：设计提案（2026-08-06，v0.4 之后）
> **背景**：玩家命题——"现在的游戏本质是堆量、堆设计；既然要做以 Agent NPC 为主的游戏，item 维度就应该无限大；人工设计不了无限资产，无限资产也不可能被消费完；所以能不能让 NPC 自己触发游戏资产的设计，按照他们的意志去改变游戏本身。"
> **结论先行**：**可行**，且本项目是少数"地基天然合适"的架构。核心洞察：**资产原型 = 带结构化参数的知识**——NPC 设计资产，就是固化一条"可执行知识"。整个机制复用现有知识引擎，不新建独立系统。
> **计划影响**：主线 Phase 0–4 顺序**不变**；新增远期支柱 **Phase 5：世界自生成**；Phase 2 顺手铺垫"资产数据化"地基（低成本）。
> **配套**：路线图见 `docs/design-master-plan-2026-08-04.md` §4 Phase 5。

---

## 0. TL;DR（三句话）

1. **可行**。本项目的知识引擎（观察→传播→质疑→固化）已经是一套完整的"社会共识机制"——它是"设计权社会化"的现成载体，只需要把资产原型定义成知识的一个子类型。
2. **"无限"的正确形态**：不是无限物品数量（那会不可读、不可维护），而是**资产类型空间开放 + 资产生命周期**——构想→试用→固化→失传→考古复兴。"遗忘"是无限生成的另一半，它让世界永远保持可读。
3. **反失控设计**：创作有成本（材料/时间/技能）、进入世界要过社会共识门槛（固化阈值）、失传有机制（生命周期）——三重约束下，无限生成不会演变成垃圾数据海。

## 1. 命题重述（先厘清三个被混淆的词）

### 1.1 为什么现有游戏"堆量"而不够

开放世界游戏的内容是**开发者预设计 → 玩家消费**的单向管道。量再大也有边界，且资产与 agent 无关——物品不知道谁造了它、谁用过它、它在小镇历史上意味着什么。玩家的核心抱怨本质是：**内容与"人"（agent）脱节**。

### 1.2 "无限资产" ≠ 无限物品数量

- 无限物品数量：不可读、不可维护、数据爆炸——不是目标。
- 真正的"无限"：**类型空间开放**——物品、配方、设施、事件模板、组织都可以由世界内部产生；产生多少由社会共识决定，而非设计表。
- 佐证：Dwarf Fortress 的物品不过几十种，但每件物品都带**生平链**（锻造者、材料来源、经历的历史事件）——游戏性来自"语义"，不来自"数量"。

### 1.3 "不可能被消费完"——语义资产本来就不靠消费

传统 RPG 资产的意义是"被消耗/被使用"（数值卡片）。但语义资产的价值在**关系**：

```
一件物品的价值 = 创造者的意图 + 制作过程 + 使用历史 + 关联的知识 + 社会共识
```

一把"托林在第十三日打的锄头"，因为托林用它掘开了矿洞东壁、挖出一块刻着旧文字的矿石、矿石的知识又在广场传开——它的价值是**它背后的故事链**，不需要被消耗，甚至不应该被消耗。**游戏资产从"消耗品"变为"文物"。**

### 1.4 "NPC 设计资产" ≠ NPC 当策划

不是让 agent 自由创作（那必然产生垃圾），而是**设计权社会化**：

- agent 产生**创作意图**（基于自己的目标/技能/知识/处境）
- 产出的是**原型提案**（结构化，带受限参数）
- 提案要**过社会共识门槛**才能成为世界事实（有 agent 愿意试用、试用者传播、固化）
- 开发者保留**审核与回滚**能力

一句话：**进入世界的权利属于社会共识，不属于单个 agent，也不属于设计表。**

## 2. 可行性论证

### 2.1 已具备的地基（本项目独有的优势）

| # | 现有机制 | 为什么它是地基 |
|---|---|---|
| 1 | **知识引擎**（KnowledgeClaim 观察/传播/质疑/固化） | 现成的"社会共识机制"。资产固化完全复用：私有构想→群体试用→公共固化，置信度门槛、反驳、冲突解决全部现成 |
| 2 | **单一数据层** storage.py + schema 版本自动重建 | 新增资产表 = 一次 DDL，schema 版本不符自动重建，加资产列/表成本极低 |
| 3 | **供需定价已存在**（world.py prices） | 新资产的价格不需要设计——供需比自动涌现，价格区间被 base 价格钳制（50%–200%） |
| 4 | **LLM 每日限次 + mock 兜底** | 创作是低频高价值动作（见 3.5 冷却），每日 10 次限额足够；核心机制（模板+参数抽取）纯规则，**无 key 也能完整演示** |
| 5 | **世界观契合**：末世重建 + 遗迹考古 | "失传→考古复兴"天然叙事；events.py 已有"金色发现"事件作为复兴入口 |
| 6 | **decide() 五层决策** | 插入"创作意图"层即可，不破坏现有节奏 |

### 2.2 需要新增的四个能力

1. **资产数据化**：物品/配方/设施定义从代码硬编码挪入数据行（type/instance 分离 + 执行器 registry）——新资产插入数据即可，不改代码。
2. **可执行知识**：knowledge.py 的 claim 扩展 `claim_type`（recipe/design/facility/event_template），claim 保留自然语言（语义），附带结构化参数模板（数值）。
3. **创作决策层**：decide() 检测"需求缺口 × 个人目标 × 技能 × 知识"→ 触发创作意图 → 模板 + 受限参数抽取出原型提案。
4. **三重校验门**：规则门（可计算）/ 社会门（试用+传播+固化）/ 开发者门（日志+回滚+封禁）。

### 2.3 为什么不会失控（反平衡三原则）

| 失控方式 | 对策 | 机制 |
|---|---|---|
| 无限创作 | **创作有成本**：材料 + 时间 + 技能门槛 + 冷却（每 agent 数日 1 次） | 创作者不可能无限造，如同现实发明有成本 |
| 垃圾资产进世界 | **社会共识门槛**：新资产必须先有 agent 愿意花成本"试用"，试用结果/传播接受率决定置信度，固化阈值与知识一致（0.85 + 5 agent） | 没人要的构想自然夭折，无需人工裁决 |
| 数据无限膨胀 | **生命周期 + 遗忘**：活跃集 → 档案馆 → 失传池 → 考古复兴（接"金色发现"事件）；前端只读活跃资产 | 无限生成，世界保持可读 |

## 3. 核心机制设计

### 3.1 资产生命周期状态机

```
 idea(构想) ──提案通过规则门──> prototype(原型)
    ▲                              │ 有 agent 愿意试用(花成本)
    │                              ▼
 rediscovered(考古复兴)         used(试用/使用)
    ▲                              │ 试用成功 + 传播接受
    │                              ▼
    └── lost(失传, 入档案馆) <── solidified(固化, 成为世界事实)
                                    │ 被反驳/被替代/长期无人使用
                                    ▼
                              evolving(演化/被修正, 版本+1)
```

- **每个状态都映射到知识引擎既有机制**：提案=新知识（source=推理，confidence 0.4）；试用=传播；固化=知识固化；反驳=质疑；失传=置信度衰减归零 + 移入档案馆。
- **失传 ≠ 删除**：资产从"活跃集"移入"档案馆"，保留完整故事链（创造者/首次试用者/固化见证者/最后使用者），成为**考古素材**。
- **考古复兴**：失传资产按概率被"金色发现"/遗迹事件重新发现 → 重新进入活跃集，confidence 重置为传闻级 → 再次走社会传播（旧物重见天日的叙事由此涌现）。

### 3.2 资产原型 schema（数据化）

统一表 `assets`（type/instance 分离：原型是"设计"，制作/使用的实物是实例）：

```sql
CREATE TABLE assets (
  asset_id      TEXT PRIMARY KEY,      -- 原型唯一 ID（如 asset_recipe_hoe_v1）
  asset_type    TEXT NOT NULL,         -- recipe | item | facility | event_template | organization
  name          TEXT NOT NULL,         -- 中文名（LLM 语义增强，mock 时用模板名）
  desc          TEXT NOT NULL,         -- 一句话描述（进入档案/日报的素材）
  params_json   TEXT NOT NULL,         -- 结构化参数（见 3.4）
  creator_id    TEXT NOT NULL,         -- 创造者 agent_id（故事链起点）
  status        TEXT NOT NULL,         -- idea|prototype|used|solidified|lost|rediscovered
  confidence    REAL DEFAULT 0.4,      -- 复用知识置信度语义
  version       INTEGER DEFAULT 1,
  created_at    REAL NOT NULL,
  solidified_at REAL,
  last_used_at  REAL,                  -- 用于失传判定（长期无人使用→lost）
  history_json  TEXT,                  -- 故事链：首次试用者/固化见证者/最后使用者
  banned        INTEGER DEFAULT 0      -- 开发者封禁标记（回滚/审核门）
);
```

- **执行器 registry**：代码里保留"类型注册表"（每种 asset_type 的执行/校验函数），具体定义在数据行。**新增同类资产零代码，新增资产类型才需要开发者扩展**——类型空间有限且受控，实例空间无限且自由。
- 实物实例不落全表：实例 = `(asset_id, owner, count, born_at, used_history)`，走现有 inventory/库存逻辑即可。

### 3.3 可执行知识（配方示例）

知识引擎扩展：claim 增加 `claim_type` 与 `params_json`。一条"配方知识"= 自然语言语义 + 结构化参数：

```json
{
  "claim_type": "recipe",
  "claim": "把 3 份矿石和 2 份材料在工坊烧一整天，能打出一把铁锄",
  "params": {
    "inputs":  {"ore": 3, "materials": 2},
    "outputs": {"hoe": 1},
    "skill_min": 2,
    "location": "workshop",
    "duration_hours": 6
  }
}
```

- **模板 + 参数插槽**：LLM 只负责语义部分（命名/描述/意图），**数值由规则引擎从受限范围抽取**（参数插槽带 min/max/步长，由资产类型模板定义）。这解决"LLM 输出不可控"——LLM 永远不直接决定数值。
- 固化的配方知识可直接被其他 agent 执行（craft 动作从"查代码"改为"查资产库"）。

### 3.4 创作意图的生成（决策层）

**触发条件**（decide() 新增一层，规则为主，LLM 增强语义）：

1. **需求缺口检测**：感知到价格失衡（食物价高→想新采集法）、工具短缺、修缮停滞、未满足的知识冲突……（world.prices / resources / 事件输入）
2. **动机匹配**：缺口与本人目标/职业/技能相关（铁匠想新工具、农民想新种法、艾莉丝想新故事=event_template）
3. **性格倾向**：创意型人格（莉娜/艾莉丝）创作概率更高
4. **冷却**：每 agent 3 天最多 1 次创作尝试（LLM 限额内：每日限次 10 次，创作约占 1 次）

**产出**：`AssetProposal`（原型提案）→ 走规则门 → 进 prototype 池等待社会试用。

### 3.5 三重校验门

| 门 | 内容 | 失败后果 |
|---|---|---|
| **规则门**（可计算，提案时） | 参数在模板允许范围；成本>0；与已有资产查重；**不违反已固化知识**（如"矿石有毒"已固化→含矿配方被拒） | 提案夭折，进入 agent 日记（"托林想打铁锄，但记起矿石有毒，作罢"——失败也是叙事） |
| **社会门**（涌现，试用期） | 其他 agent 基于效用决定是否花成本试用；试用成功率 + 传播接受率 → confidence；固化阈值 0.85 + 5 agent 接受（与知识固化一致） | 无人试用→置信度衰减→失传 |
| **开发者门**（异步） | 全量资产可查（前端"资产浏览器"）、可封禁（banned=1）、可回滚；一切创作留日志 | 封禁即从活跃集移除，不删故事链 |

### 3.6 价值涌现（定价）

- 新资产**没有设计价格**：价格 = 供需比 × base 区间钳制（现有 `_update_prices` 机制自动适用，`get_price` 对未知资源有默认值兜底）。
- 语义稀有度加成（P3 可选）：失传后被考古复兴的资产获得"文物溢价"（故事链长度进入定价公式）——**故事直接变成经济价值**。

### 3.7 无限与遗忘（数据治理）

- **活跃集**：solidified 且近期在用的资产 → 前端/决策可见（数量受社会共识自然约束，一般几十件内）。
- **档案馆**：lost 资产全量保留 → 开发者查询、考古复兴素材、日报历史。
- **前端**：只读活跃集；档案/日报展示资产故事链（"这把锄头：托林所造 → 罗文第一次试用 → 用了 30 天 → 失传于矿洞东壁"）。

## 4. 实施路线（三阶段，映射主计划）

> 总原则：**先让资产成为数据，再让 NPC 成为作者，最后让时间成为裁判。**

### P1 资产数据化（地基）——可与 Phase 2 经济闭环并行

| 任务 | 内容 | 验收 |
|---|---|---|
| 1.1 配方/物品数据化 | 现有 craft 配方/物品定义从常量/代码挪入 storage 数据行；执行器 registry | 新增一条配方只插数据行，不改代码；现有行为不回归 |
| 1.2 资产表 DDL | 3.2 的 `assets` 表 + schema 版本升级 | 冒烟测试覆盖资产 CRUD |
| 1.3 前端只读展示 | 工坊面板显示"小镇现有配方"（数据驱动） | 工坊不再是写死列表 |

### P2 创作与校验（NPC 开始设计）——Phase 3 之后

| 任务 | 内容 | 验收 |
|---|---|---|
| 2.1 可执行知识 | knowledge.py 支持 claim_type + params_json；固化阈值同知识 | 一条"配方知识"固化后可直接被制作 |
| 2.2 创作决策层 | decide() 增创作意图层（3.4 触发规则 + 冷却） | 无 key（mock）也能产生结构合法的提案 |
| 2.3 三重校验门 | 规则门实现；社会门（试用决策 + 传播置信度）；开发者门（资产浏览器 + 封禁） | 垃圾提案被规则/社会门拦截有日志 |
| 2.4 玩家同权 | 玩家可提资产提案（走同管线） | 玩家设计的东西能被小镇接受或拒绝 |

### P3 生命周期与考古（无限与遗忘闭环）

| 任务 | 内容 | 验收 |
|---|---|---|
| 3.1 失传机制 | last_used_at 超期 + confidence 归零 → lost，入档案馆 | 长期无人使用的资产自动失传 |
| 3.2 考古复兴 | 失传资产接入"金色发现"/遗迹事件池，概率重现 | 考古发现展示完整故事链 |
| 3.3 文物溢价 | 故事链长度进入定价 | 故事变成经济价值 |
| 3.4 规模化护栏 | 活跃集上限、创作冷却调参、数据 VACUUM 策略 | 100+ 天运行无膨胀失控 |

## 5. 风险登记

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 生成资产语义稀碎（世界观崩坏） | 中 | 高 | 模板+受限参数；固化需社会共识；规则门校验"不违反已固化知识"；开发者封禁 |
| LLM 成本（创作调用） | 低 | 中 | 冷却（3 天/agent/次）；每日限次已存在；核心机制纯规则，mock 可完整跑 |
| 资产超发冲击经济 | 中 | 中 | 创作有成本 + 供需定价自动吸收；平衡观察依赖 Phase 2 经济闭环先活 |
| 数据膨胀 | 中 | 中 | 生命周期（失传→档案馆）+ 活跃集上限 + VACUUM（Phase 4.3 已有） |
| 与现有 Phase 冲突 | 低 | 高 | **Phase 0–4 顺序不变**；P1 数据化是纯重构（行为不回归），可随时停 |
