# K-town 美术方向 v2：绘本水彩舞台

> **状态**：首周纵切片的视觉规范
> **日期**：2026-08-23
> **关联文档**：`gameplay-design-v5.md`、`world-view-v3.md`、`docs/plans/2026-08-23-rebuild-plan.md`

## 0. 视觉目标

K-town 的第一眼应该是“这里有人正在生活”，而不是“这里有一组状态指标”。界面服务于观察、选择和反馈：玩家能看见谁在忙、谁在犹豫、天气如何改变场景，以及自己的选择留下了什么。

当前的水彩 UI、像素地图和大量监控式卡片缺少统一舞台。v2 统一为 **绘本水彩舞台**：低饱和水彩色块、略有抖动的墨线、纸张纹理和可辨识的居民姿态。地图不再只是背景，UI 卡片也不再压过居民。

## 1. 风格锚点

### 1.1 关键词

温暖、手作、潮湿的河谷空气、可读的日常动作、克制的奇异感。

### 1.2 统一规则

- 中央主画面是生活舞台，默认能看到全镇活动或至少多个地点的活动摘要。
- 建筑、道路、居民和天气使用同一套纸面材质，不混用没有规则的 8bit 像素块。
- 线条粗细允许轻微不一致，但必须保持轮廓可辨；不要把所有元素做成标准几何图标。
- 颜色必须来自设计 token；新增颜色先补 token，再写组件样式。
- 卡片圆角不超过 8px，重复内容用紧凑列表而不是层层嵌套卡片。
- 首屏不使用大面积渐变、装饰性光球或与玩法无关的插画。

### 1.3 颜色令牌

建议保留暖纸色作为底色，同时用不同色相表达状态，避免整页落入单一棕色或蓝灰色：

| 用途 | 方向 | 示例 token |
|---|---|---|
| 纸面/背景 | 暖白与浅灰，不刺眼 | `--paper-0`、`--paper-1` |
| 墨线/正文 | 深棕黑，保证对比度 | `--ink-900`、`--ink-600` |
| 河谷/晴天 | 青绿色与天蓝 | `--river-500`、`--sky-400` |
| 工坊/材料 | 铁灰与木色 | `--iron-500`、`--wood-500` |
| 情绪警示 | 琥珀、红、靛青分开表达 | `--mood-worry`、`--mood-anger`、`--mood-sad` |
| 正向结果 | 绿色，不用纯金色铺满 | `--success-500` |

正文、按钮和警告文本需要通过现有对比度检查。不要用透明度降低到无法阅读的“水彩灰”。

## 2. 生活舞台构成

### 2.1 地图

- 保留 SVG/Canvas 作为可交互地图，先做一张可靠的关键场景，再扩展五地点。
- 画面同时显示地点关系、居民位置和天气层；点击地点打开上下文，不把其他地点全部隐藏。
- 道路用手绘土路连接，节点有轻微不规则边缘；禁止每次状态刷新时随机改变道路几何。
- 当前地点用轻微描边和居民动作聚焦，不使用巨大高亮遮住背景生活。

### 2.2 居民

每位居民至少需要以下视觉信息：

- 职业可识别的道具或姿态：铁锤、木料、公告纸、采集篮等；
- 站立、工作、交谈、焦虑等待四类基本姿态；
- 天气反馈：雨天收肩、撑伞、搬材料，晴天动作更舒展；
- 情绪只用作行为和少量表情/光环提示，不能依赖彩色圆点解释人格；
- hover 或点击显示姓名，避免地图被文字填满。

### 2.3 建筑与修缮

工坊屋顶必须有三种稳定状态：漏雨、临时遮雨、正式修好。差异应同时出现在：

- 屋顶轮廓和遮雨材料；
- 雨水滴落、窗光和室内活动；
- 请求卡和傍晚因果回信。

先完成工坊这一张关键场景，再复制状态表达给其他地点。

## 3. 天气、时间与反馈

天气和时段是叙事反馈，不是持续播放的装饰：

- 雨：稀疏、稳定的雨线；工坊漏雨处有明确滴落；低性能模式减少粒子数量。
- 晴：地面明度提高，居民姿态放松，河谷边缘有轻微风动。
- 傍晚：天空和纸面颜色变暖，广场出现聚集和灯火。
- 夜间：不使用全屏黑幕；用深色纸面、窗光和少量可见路径表达“镇上睡了”。
- 危机：只在事件发生时使用短促震动、局部色带或声音提示；避免常驻红色警报。

### 3.1 动效实现约束

- 粒子拥有明确生命周期和 seed，不能在每次 WebSocket state 更新时重建。
- 动效由天气、时段、事件和建筑状态驱动；所有触发点可在日志中定位。
- 支持 `prefers-reduced-motion`，减少粒子和震动但不隐藏信息。
- 动画不改变布局尺寸；按钮、计数器、地图节点使用稳定的宽高或纵横比。

## 4. UI 信息层级

### 4.1 首屏

1. **中央舞台**：居民正在做什么、天气和地点关系。
2. **今日三条线**：居民请求、镇上压力、可跟进线索。
3. **当前地点行动**：只列 2-4 个具体回应，显示对象、时间成本和作用方向。
4. **顶栏状态**：日期、时段、剩余行动；详细数值进入档案或开发抽屉。

不要在首屏同时放任务、危机、进度、知识和调试面板。它们由当前请求和事件点击进入。

### 4.2 居民档案

档案顺序固定为：

```text
姓名/职业 → 正在做什么 → 当前感受 → 感受原因 → 行为倾向 → 你能回应什么
```

四维情绪条、关系数值、知识置信度属于可展开的解释层。任何数字旁边都要能找到来源事件或一句自然语言原因。

### 4.3 移动端

- 右侧“今日三条线”改为底部 sheet 或分段面板，不得直接隐藏。
- 地图和行动入口保持稳定高度，避免文本换行导致舞台跳动。
- 图标按钮使用现有图标库或熟悉符号；不为简单箭头、保存、返回创建文字胶囊按钮。
- 不在界面上常驻展示大段“如何使用”说明；帮助入口才打开简短提示。

## 5. 资产优先级

### P0：必须完成

- 一张雨天工坊关键场景：托林、莉娜、漏雨屋顶、干木料、可交互行动反馈；
- 广场、工坊、河谷野径的可读地图节点和手绘道路；
- 12 位居民的职业色/道具/姿态最小集合；
- 纸面纹理、时段色、雨层和屋顶三阶段状态。

### P1：纵切片完成后

- 学校和矿洞的地点变体；
- 归灯集的灯火、摊位和人群动画；
- 传闻与知识传播的纸条、公告或口述视觉表现；
- 事件状态的声音提示和可选环境音。

### P2：暂缓

- 大量独立 raster 角色表情；
- 复杂粒子特效、镜头后处理；
- 主题皮肤、装饰性设置页和成就徽章。

## 6. 美术验收

- 首屏截图中，玩家先看到居民和天气，再看到数值和按钮。
- 同一张地图在晴天、雨天、傍晚、夜间能通过稳定的颜色、动作、窗光看出状态。
- 工坊屋顶三阶段无需阅读数字即可区分。
- 任一按钮文字和图标在桌面、窄屏均不溢出，不遮挡相邻内容。
- 视觉没有“水彩 UI + 8bit 像素地图”的割裂感；颜色、线条、纹理和动效遵守同一规范。
- 关闭动效后，天气、危机、修缮和请求结果仍然可读。
